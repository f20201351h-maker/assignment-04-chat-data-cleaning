# Reproducing the cleaned corpus

Needs Python 3.11+ (developed on 3.14) with `numpy pyarrow huggingface_hub tokenizers xxhash py3langid pytest`,
and Node 18+ for the site build. No GPU. Peak RAM was about 2 GB.

```bash
python scripts/download.py          # pinned upstream files -> data/raw, data/eval; hashes -> artifacts/sources.json
python scripts/run_pipeline.py      # all nine stages -> data/clean, data/quarantine, artifacts/*.json
python scripts/audit_stats.py       # recompute headline numbers from the files, check invariants
python scripts/measure_upstream.py  # backslash/markup loss in the raw Glaive file
python scripts/train_classifier.py  # quality layer 2 (needs the LLM labels in data/audit/labels)
python scripts/build_fp_audit.py    # summary of the false-positive review (needs data/audit/fp_audit_raw.json)
python scripts/check_determinism.py # run the pipeline again into a temp folder and compare hashes
python scripts/run_tests.py         # unit tests, result recorded in artifacts/audits/tests.json
python scripts/build_site_data.py   # artifacts -> site/data/site.json
node site/build.mjs                 # checks + copy to site/dist
```

Two inputs are human/LLM work and are not regenerated by a script: the 600 classifier labels
(`data/audit/labels/`, rubric in `docs/notes/labelling_rubric.md`) and the false-positive / name reviews
(`data/audit/fp_audit_raw.json`, `data/audit/ner_audit_raw.json`). Their samples are drawn with fixed seeds by
`scripts/classifier_sample.py` and `scripts/sample_quarantine.py`.

`data/` is git-ignored: the raw and cleaned conversations stay on disk and are not redistributed.
Everything under `artifacts/` is small, generated, and committed.

## What makes it deterministic

* Upstream files are pinned by commit and checked by sha256 (`artifacts/sources.json`).
* The tokenizer used for every count is pinned (`Qwen/Qwen3-0.6B` at a fixed revision).
* No randomness without a fixed seed (MinHash permutations, review samples, classifier sample).
* Documents keep their source order; near-duplicate clusters keep their lowest index.
* Document ids are `sha256(cleaned canonical text)`, shard ids come from the shard's content hash, and the
  corpus id comes from the shard hashes. Timestamps live only in `artifacts/run_info.json`, which is not part
  of any id.
* Script hashes are taken over LF-normalised source, so a Windows and a Linux checkout give the same hash.
